# ตั้งค่าปลายทางสำรองเป็น Synology NAS (ผ่าน SFTP)

คู่มือนี้ใช้แทนข้อ 2–3 ของ [`README.md`](README.md) เมื่อเลือกเก็บสำรองบน NAS ของวิทยาลัย (ITUDTC_NAS — `10.30.0.2`)
ทำเสร็จแล้วกลับไปทำ **README ข้อ 4 เป็นต้นไป** (ตั้งค่าสคริปต์ → ทดสอบ → cron → healthchecks) ตามเดิม สคริปต์ไม่ต้องแก้ ต่างกันแค่ชื่อ remote คือ `nas-crypt`

> **ข้อควรรู้ก่อนเริ่ม**
> - ชื่อเมนูและตำแหน่งการตั้งค่าใน DSM ด้านล่างเขียนตาม DSM 7.x ทั่วไป ของจริงอาจต่างเล็กน้อยตามรุ่น DSM ที่ติดตั้ง — ให้ยึดตามที่เห็นบนหน้าจอ
> - สคริปต์และขั้นตอนนี้ **ผ่านการทดสอบกับ SFTP server จำลอง** ไม่ใช่ NAS จริง จึงต้องทดสอบทีละขั้นตามข้อ 5 และตรวจผลด้วยตัวเอง
> - NAS อยู่ที่วิทยาลัยเดียวกับเซิร์ฟเวอร์ ถ้าไฟไหม้/น้ำท่วม/ไฟกระชากหรือโดนแรนซัมแวร์ที่ลามทั้งเครือข่าย ทั้งสองเครื่องอาจเสียพร้อมกัน — ดูข้อ 7 เรื่องสำเนานอกอาคาร

## ภาพรวม

```
เซิร์ฟเวอร์ qa-ems ──(SFTP, เข้ารหัสด้วย rclone crypt ก่อนส่ง)──▶ NAS 10.30.0.2
                                                                └── /alumni-backup/data/   (ชื่อไฟล์และเนื้อหาอ่านไม่ออก)
```

ข้อมูลถูกเข้ารหัสที่เซิร์ฟเวอร์ก่อนส่ง แม้คนที่มีสิทธิ์ admin บน NAS ก็เปิดอ่านข้อมูลศิษย์เก่าและสลิปไม่ได้ ถ้าไม่มีรหัส crypt

## 1) เตรียมฝั่ง NAS (ทำใน DSM ด้วยบัญชี admin)

> เข้า DSM ผ่าน HTTPS (`https://10.30.0.2:5001`) แทน `http://...:5000` เพื่อไม่ให้รหัสผ่านวิ่งบนเครือข่ายแบบอ่านได้

**1.1 สร้าง Shared Folder เฉพาะ** — *Control Panel → Shared Folder → Create*

- ชื่อ: `alumni-backup` (ใช้ชื่อภาษาอังกฤษล้วน ไม่มีเว้นวรรค)
- **ไม่ติ๊ก "Enable Recycle Bin"** — ไม่เช่นนั้นไฟล์เก่าที่สคริปต์ลบตามนโยบายจะไปกองในถังขยะและกินพื้นที่โดยไม่มีใครเห็น (ถ้าต้องการกันลบพลาด ให้ใช้ snapshot ตามข้อ 6 แทน)
- ถ้าให้เลือก: เปิด **Data checksum for advanced data integrity** (เฉพาะโวลุ่ม Btrfs) — ไม่บังคับ
- ไม่ต้องเข้ารหัสโฟลเดอร์ของ DSM ซ้ำ เพราะ rclone crypt เข้ารหัสให้แล้ว (และโฟลเดอร์ที่เข้ารหัสของ DSM ต้องคอยปลดล็อกหลังรีบูต ทำให้สำรองหยุดเงียบ ๆ ได้)

**1.2 สร้างผู้ใช้สำหรับสำรองโดยเฉพาะ** — *Control Panel → User & Group → Create*

- ชื่อ: `backup-alumni` ตั้งรหัสผ่านยาวและสุ่ม (16 ตัวอักษรขึ้นไป) ไม่ต้องอยู่กลุ่ม `administrators`
- Shared folder permissions: `alumni-backup` = **Read/Write**, โฟลเดอร์อื่นทั้งหมด = **No access**
- Application permissions: อนุญาต **FTP** (ซึ่งครอบคลุม SFTP) และปฏิเสธที่เหลือ (DSM, File Station ฯลฯ ไม่ต้องให้)
  ในบาง DSM หน้านี้อยู่ที่ *Control Panel → Application Privileges*

เหตุผล: ถ้ารหัสผ่านบัญชีนี้หลุดจากเซิร์ฟเวอร์ ผู้บุกรุกจะทำได้แค่กับโฟลเดอร์ `alumni-backup` ไม่ใช่ทั้ง NAS

**1.3 เปิดบริการ SFTP** — *Control Panel → File Services → FTP → แท็บ SFTP*

- ติ๊ก **Enable SFTP service** พอร์ต 22 (ค่าเริ่มต้น)
- ไม่ต้องเปิด FTP ธรรมดา / FTPS

> อย่าเปิด SSH terminal (*Control Panel → Terminal & SNMP*) เพิ่มถ้าไม่จำเป็น การสำรองใช้แค่ SFTP

**1.4 จำกัดว่าใครเข้า NAS ได้** — *Control Panel → Security → Firewall*

สร้างกฎให้อนุญาตพอร์ต SFTP (22) **เฉพาะ IP ของเซิร์ฟเวอร์ qa-ems** (และ IP เครื่องแอดมินที่ต้องใช้) แล้วปฏิเสธที่เหลือ
ระวัง: ก่อนบันทึกกฎ ต้องแน่ใจว่ายังเข้า DSM ของตัวเองได้ (เพิ่มกฎอนุญาต IP/พอร์ต 5001 ของเครื่องคุณก่อน) ไม่เช่นนั้นจะล็อกตัวเองออก

**1.5 ตรวจพื้นที่และสุขภาพดิสก์** — *Storage Manager*

- พื้นที่ว่างควรมากกว่าขนาดข้อมูลทั้งหมดของระบบอย่างน้อย 3–5 เท่า (มีสำเนารายวัน 30 วัน + รายเดือน 6 เดือน + ไฟล์ที่พักไว้ใน `minio-deleted`)
  ดูขนาดจริงบนเซิร์ฟเวอร์ได้ด้วย `docker system df -v` และ `du -sh` ของ volume MinIO/Postgres
- สถานะดิสก์ต้อง Healthy และตั้งแจ้งเตือนอีเมลของ DSM ไว้ (*Control Panel → Notification*) เพื่อให้รู้เมื่อดิสก์เริ่มเสีย

## 4) สร้าง remote `nas` และ `nas-crypt`

**4.1 remote `nas` (SFTP ไปยัง NAS)**

```bash
rclone config
```

`n` → name: `nas` → Storage: `sftp` (พิมพ์ชื่อหรือเลือกจากเลขในรายการ) →
host: `10.30.0.2` → user: `backup-alumni` → port: `22` (Enter) →
password: เลือก `y` แล้วพิมพ์รหัสผ่านของบัญชีข้อ 1.2 (rclone จะเก็บแบบ obscure) →
ข้อที่เหลือกด Enter ตามค่าเริ่มต้นจนถึง `y` (Yes this is OK) → `q`

ทำแบบไม่โต้ตอบก็ได้ (พิมพ์รหัสผ่านลงในประวัติคำสั่ง — ใช้เฉพาะถ้าไม่ห่วงเรื่องนี้):

```bash
rclone config create nas sftp host 10.30.0.2 user backup-alumni port 22 pass "$(rclone obscure 'รหัสผ่านที่นี่')"
```

**4.2 ล็อกลายนิ้วมือ host key ของ NAS** (กันถูกหลอกให้ส่งข้อมูลไปเครื่องปลอม)

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keyscan -p 22 10.30.0.2 >> ~/.ssh/known_hosts
ssh-keygen -lf ~/.ssh/known_hosts | tail -n 1        # ดูลายนิ้วมือ ควรตรงกับที่ NAS แสดงหรือที่ผู้ดูแล NAS ยืนยัน
rclone config update nas known_hosts_file ~/.ssh/known_hosts
```

**4.3 ทดสอบว่าเข้าได้และดู "หน้าตา" ของโฟลเดอร์ราก**

```bash
rclone lsd nas:
```

ต้องเห็นโฟลเดอร์ `alumni-backup` (SFTP ของ Synology มักแสดง shared folder ที่ราก `/` ทำให้ path เป็น `/alumni-backup/...`)
**ถ้าเห็นรูปแบบอื่น** เช่น ต้องผ่านโฟลเดอร์ `volume1` ก่อน หรือ path เริ่มต้นต่างจากนี้ ให้ปรับ path ในข้อ 4.4 ให้ตรงกับที่เห็นจริง — ทดสอบด้วย `rclone lsd nas:alumni-backup` หรือ `rclone lsd nas:/volume1/alumni-backup` จนกว่าจะเจอ

**4.4 remote เข้ารหัส `nas-crypt`**

```bash
rclone config
```

`n` → name: `nas-crypt` → Storage: `crypt` → remote: `nas:/alumni-backup/data` (ตามที่ตรวจในข้อ 4.3) →
filename_encryption: `standard` → directory_name_encryption: `true` →
Password: เลือก `g` (generate) ความยาว 1024 bits → Password2 (salt): เลือก `g` เช่นกัน → `y` → `q`

> ### ⚠️ สำคัญที่สุดของทั้งชุด
> รหัสผ่านสองตัวใน `nas-crypt` **ไม่สามารถกู้คืนได้** ถ้าหาย ข้อมูลสำรองทั้งหมดบน NAS จะถอดรหัสไม่ได้อีกตลอดไป
> ให้ทำทันที:
> 1. รัน `rclone config file` เพื่อดูตำแหน่งไฟล์ `rclone.conf`
> 2. คัดลอกไฟล์นั้นเก็บไว้ **อย่างน้อย 2 แห่งที่อยู่นอกเซิร์ฟเวอร์ และไม่ใช่ NAS เครื่องนี้** (เช่น ตัวจัดการรหัสผ่านของหน่วยงาน, แฟลชไดรฟ์ในตู้เซฟ)
>    ไฟล์นี้มีทั้งรหัสผ่านเข้า NAS และรหัส crypt — เก็บเหมือนกุญแจห้องเซิร์ฟเวอร์
> 3. `chmod 600 ~/.config/rclone/rclone.conf`
> 4. ให้ผู้ดูแลระบบอย่างน้อย 2 คนรู้ว่าไฟล์นี้อยู่ที่ไหน
>
> ห้ามเก็บสำเนา `rclone.conf` ไว้บน NAS ที่เป็นที่สำรองเอง — ถ้า NAS เสียจะเสียทั้งข้อมูลและกุญแจพร้อมกัน

**4.5 ทดสอบเขียน/อ่านผ่าน crypt**

```bash
echo hello | rclone rcat nas-crypt:alumni/_probe.txt
rclone cat nas-crypt:alumni/_probe.txt          # ต้องพิมพ์ hello
rclone lsf nas:/alumni-backup/data -R            # ต้องเห็นชื่อไฟล์เป็นตัวอักษรสุ่ม = เข้ารหัสจริง
rclone deletefile nas-crypt:alumni/_probe.txt
```

## 5) ตั้งค่าสคริปต์แล้วทดสอบ (กลับไป README ข้อ 4–5)

```bash
cd /opt/alumni-system/backup
cp backup.env.example backup.env && chmod 600 backup.env
grep '^RCLONE_REMOTE' backup.env                  # ต้องเป็น RCLONE_REMOTE=nas-crypt (ค่าเริ่มต้นของไฟล์ตัวอย่าง)

bash backup.sh --check
bash backup.sh                                    # สำรองจริงครั้งแรก
bash restore.sh list
bash restore.sh test
```

**ทดสอบเพิ่มสำหรับ NAS:** รัน `bash backup.sh` **ซ้ำอีกครั้งทันที** รอบที่สองต้องเสร็จเร็วมากและ log ต้องไม่ส่งไฟล์ MinIO ซ้ำ
ถ้ารอบสองอัปโหลดไฟล์เดิมใหม่ทั้งหมด แปลว่า NAS ไม่ยอมเก็บเวลาแก้ไขไฟล์ (modtime) — ให้เพิ่ม `--size-only` ใน `RCLONE_FLAGS` ของ `backup.env`
(ยอมแลกความแม่นยำกรณีไฟล์เปลี่ยนเนื้อหาโดยขนาดเท่าเดิม ซึ่งไฟล์สลิป/รูปแทบไม่เกิดขึ้น)

**พฤติกรรมของ SFTP ที่ต่างจาก Drive (ไม่ต้องทำอะไร แค่รู้ไว้)**

- SFTP คัดลอกไฟล์ฝั่ง NAS ด้วยตัวเองไม่ได้ (ไม่มี server-side copy) — สำเนา dump รายเดือนจึงถูกดาวน์โหลดแล้วอัปโหลดกลับ ใช้เวลานานขึ้นเล็กน้อยแต่ไฟล์ dump เล็ก และทดสอบแล้วทำงานได้
- ไม่มีค่า hash ให้ตรวจหลังส่ง สคริปต์จึงเทียบด้วยขนาดไฟล์ (`--size-only`) — เป็นการตรวจว่าไฟล์ครบ ไม่ใช่การตรวจว่าเนื้อหาเหมือนทุกบิต (`restore.sh test` ที่กู้จริงเป็นตัวพิสูจน์ที่ดีที่สุด)
- `rclone about nas:` อาจใช้ไม่ได้ ให้ดูพื้นที่ที่ *Storage Manager* ใน DSM แทน

จากนั้นทำ **README ข้อ 6 (cron)** และ **ข้อ 7 (healthchecks)** ต่อ — ข้อ 7 สำคัญเป็นพิเศษกับ NAS เพราะถ้า NAS ดับ/รหัสผ่านหมดอายุ การสำรองจะล้มเงียบ ๆ

## 6) ป้องกันข้อมูลสำรองบน NAS เอง

สคริปต์ลบของเก่าตามนโยบายเอง แต่ถ้าเซิร์ฟเวอร์ถูกเจาะ ผู้บุกรุกใช้บัญชี `backup-alumni` ลบ/ทับข้อมูลสำรองได้เช่นกัน ชั้นป้องกันที่ควรเพิ่ม:

**Snapshot Replication** (ต้องใช้โวลุ่ม Btrfs — ติดตั้งแพ็กเกจ *Snapshot Replication* จาก Package Center)

- *Snapshot Replication → Shared Folder → เลือก `alumni-backup` → Settings → Schedule*
- ตัวอย่าง: ถ่าย snapshot ทุกวัน 05:00 (หลังงานสำรอง 02:30 เสร็จ), เก็บ 14–30 ชุด
- ถ้าเป็น DSM 7.2 ขึ้นไป เปิด **Immutable snapshots** (ล็อกไม่ให้ลบจนครบกำหนด แม้แอดมินหรือแรนซัมแวร์ก็ลบไม่ได้) ตั้งกำหนดล็อกเช่น 14 วัน
- snapshot ไม่ใช่สำเนาแยกอิสระ (อยู่ในโวลุ่มเดียวกัน ดิสก์พังก็หายพร้อมกัน) แต่ป้องกันกรณีข้อมูลถูกลบ/ทับ/เข้ารหัสโดยแรนซัมแวร์ได้ดี

ถ้าโวลุ่มเป็น ext4 (ไม่มี snapshot): ให้ใช้ข้อ 7 เป็นชั้นป้องกันหลักแทน

**บัญชีและการเข้าถึง**

- เปิด 2-step verification ให้บัญชี admin ของ DSM และปิดบัญชี `guest`/`admin` ค่าเริ่มต้น (ถ้ายังเปิดอยู่)
- ตั้งอัปเดต DSM/แพ็กเกจเป็นระยะ NAS ที่เปิดพอร์ตออกอินเทอร์เน็ตเป็นเป้าโจมตีแรนซัมแวร์ที่พบบ่อย — **ไม่ควรเปิด NAS ออกอินเทอร์เน็ต** (พอร์ต 5000/5001/22 ให้เข้าถึงได้เฉพาะเครือข่ายภายในวิทยาลัย)
- ตั้ง NTP ของ NAS ให้เวลาตรงกับเซิร์ฟเวอร์ (*Control Panel → Regional Options*) เพราะสคริปต์ลบของเก่าโดยอ่านวันที่จากชื่อไฟล์ แต่ log/snapshot อ้างอิงเวลาเครื่อง

## 7) (แนะนำ) สำเนานอกอาคาร เพื่อให้ครบหลัก 3-2-1

หลัก 3-2-1: ข้อมูล **3** ชุด บนสื่อ **2** แบบ โดย **1** ชุดอยู่นอกสถานที่ — ตอนนี้มี: ข้อมูลจริง (เซิร์ฟเวอร์) + สำรองบน NAS = 2 ชุดในอาคารเดียวกัน

วิธีที่ต้องการงานเพิ่มน้อยที่สุด: ใช้ **Hyper Backup** บน NAS ส่ง `alumni-backup` ต่อไปยังปลายทางนอกอาคาร เช่น Google Drive ของวิทยาลัย
(*Hyper Backup → Create → Data backup task → Google Drive → เลือกโฟลเดอร์ `alumni-backup`*)

- ข้อมูลใน `alumni-backup` ถูกเข้ารหัสด้วย rclone crypt มาแล้ว จึงไม่ต้องเปิดเข้ารหัสซ้ำของ Hyper Backup ก็ปลอดภัย (จะเปิดเพิ่มก็ได้ แต่ต้องเก็บรหัสอีกชุด)
- ตั้งตารางหลังงานสำรอง เช่นทุกวัน 06:00 และเปิด rotation เก็บหลายเวอร์ชัน
- **กู้ในกรณีเลวร้าย (NAS พังด้วย):** กู้ไฟล์กลับจาก Hyper Backup / ดาวน์โหลดโฟลเดอร์จาก Drive มาไว้ในเครื่อง แล้วสร้าง remote `crypt` ชี้โฟลเดอร์นั้นด้วยรหัสผ่านเดิม

## แก้ปัญหาที่พบบ่อย (เฉพาะ NAS)

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `ssh: handshake failed` / `unable to authenticate` | รหัสผ่านผิด, บัญชีไม่มีสิทธิ์ FTP/SFTP (ข้อ 1.2) หรือยังไม่ได้เปิดบริการ SFTP (ข้อ 1.3) — ทดสอบด้วย `sftp backup-alumni@10.30.0.2` |
| `knownhosts: key mismatch` / `host key changed` | host key ของ NAS เปลี่ยน (อัปเดต DSM/ติดตั้งใหม่) หรือมีคนแอบอ้างเครื่อง → ตรวจกับผู้ดูแล NAS ก่อน แล้วค่อยลบบรรทัดเก่าใน `~/.ssh/known_hosts` และทำข้อ 4.2 ใหม่ |
| `connection refused` / `i/o timeout` | NAS ปิดอยู่, พอร์ตผิด, หรือ DSM Firewall บล็อก IP ของเซิร์ฟเวอร์ (ตรวจข้อ 1.4 โดยเฉพาะหลังเปลี่ยน IP เซิร์ฟเวอร์) |
| `permission denied` ตอนเขียนไฟล์ | บัญชี `backup-alumni` ไม่มีสิทธิ์ Read/Write บน `alumni-backup` หรือโควตา/พื้นที่เต็ม |
| `directory not found` ทั้งที่มีโฟลเดอร์ | path ราก SFTP ต่างจากที่คาด → ทำข้อ 4.3 ใหม่ แล้วแก้ path ของ `nas-crypt` ด้วย `rclone config update nas-crypt remote nas:<path ที่ถูก>` (ถ้าเปลี่ยน path หลังมีข้อมูลแล้ว ต้องชี้ไปที่เดิมเท่านั้น ไม่งั้นรหัสถอดไม่เจอไฟล์เดิม) |
| พื้นที่บน NAS ไม่ลดลงแม้สคริปต์ลบของเก่าแล้ว | Recycle Bin ของ shared folder ยังเปิดอยู่ (ข้อ 1.1) หรือ snapshot ยังถือไฟล์เก่าไว้ (ปกติ) |
| การสำรองรอบแรกช้ามาก | ส่งไฟล์ทั้งหมดครั้งแรกตามปกติ รอบถัดไปส่งเฉพาะส่วนที่เปลี่ยน ปล่อยให้เสร็จโดยรันใน `tmux`/`screen` |
